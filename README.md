# 跨文字商标检索的候选处置

商标咨询索引采用 UTF-8 编码，人物、单位和记录均为合成内容。

| 资料 | 字段 |
| --- | --- |
| `资料/来函.json` | `id`、`client`、`market`、`language`、`text` |
| `资料/商标档案.json` | `id`、`label`、`variant`、`market`、`category`、`nature` |
| `资料/市场类目.json` | `id`、`market`、`revision`、`parent`、`text` |

每份资料是 JSON 数组。记录中的字段值按来源原样保留为字符串，逗号和顿号可以属于字段内容。资料中可能有转述、不同的拼写以及较晚录入的更正。数字及日期在这些文件中沿用各资料自身的含义；原文位置以记录编号及文本范围定位。

Node.js 22 环境下运行以下命令可安装锁定的项目环境、检查素材格式并读取各类资料的数量。

```sh
npm ci --offline --ignore-scripts --no-audit --no-fund
npm test
npm run materials
```

`readMaterials` 只读取资料，不解析其中的正文含义。

## 生成核查范围

```sh
npm run review                 # 人工阅读的清单
npm run review -- --json       # 完整候选与证据
npm run review -- --client 河岸园艺
npm run review -- --market 松岛
```

工具把每封来函拆成「写法 × 市场 × 类目」的候选，逐条给出原文范围、纳入或仅作线索的理由、
档案命中与商品范围依据。输出只是可复核的检索线索，不代替正式注册意见。

## 处理规则

- **来函辨认**：按分句识别「现用标」「简称」「参考同行」「仅作说明」「不带某标志」等语句，
  后者不会产生申请候选。名称与「做滴灌配件」这类经营说明分开，商品范围单独列出。
- **跨文字检索**：比较顺序为同形 → 中文近形 → 同音 → 音译 → 拉丁拼写变体 → 意译 → 部分重合。
  音译使用内置无调读音表，含未收字时放弃该条证据；意译要求整词义项完整。每条命中都附语言依据。
- **市场与类目**：不同市场不合并审核范围；同一市场内可识别上下位与同级关系，但只作提示。
  类目有多版释义时取最新版，同时保留旧版并在候选上注明修订。
- **修订重看**：类目补充释义后，旧版判为不相关、新版出现商品关联的候选列入「类目修订后需重看」。
- **别名传播**：同一客户的多封来函共用一次咨询，但候选逐条保留；纠正公司简称时，
  可核对其它客户的别名库，字面完全一致的才判断为已更新或仍旧写法。
- **分派与合并**：按市场生成分派单；各分支结果合并后仍保留各自的标志、分类关系与语义证据。
  多个写法共用同一分类关系时只作提示，不合并条目。
- **描述词误用**：档案标注为「品类说明」的描述词若曾被当作多个品牌的俗称，
  `recheckDescriptiveAliases` 列出受影响的既有分派；有独立证据的候选保留并注明来源。

## 代码结构

| 文件 | 作用 |
| --- | --- |
| `materials.js` | 读取与校验三份 JSON 资料 |
| `src/extract.js` | 从来函分句抽取名称、商品与比较性提及 |
| `src/readings.js` | 汉字无调读音表与拼音转换 |
| `src/names.js` | 写法折叠、相似度、字词义项 |
| `src/compareNames.js` | 两种写法的命中类型与证据 |
| `src/catalog.js` | 市场类目修订与类目关系 |
| `src/trademarks.js` | 商标档案索引 |
| `src/relevance.js` | 商品说明与类目释义的关联 |
| `src/review.js` | 候选生成、分派、合并、修订重看 |
| `src/audit.js` | 别名传播与描述词误用核查 |
| `src/cli.js` | 命令行输出 |

无资料里出现过的字形或读音时，工具不会推断，而是放弃该条证据并提示人工确认。
